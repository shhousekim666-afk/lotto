# 로또 추천 페이지 운영

사이트: https://shhousekim666-afk.github.io/lotto/

## 매주 당첨번호 반영

1. GitHub Actions에서 **Add Lotto Round (manual)** → **Run workflow**, 브랜치 `main`을 선택합니다.
2. `회차,YYYY-MM-DD,번호1,번호2,번호3,번호4,번호5,번호6,보너스`를 입력합니다. 실제 발표된 번호만 입력합니다.
3. `rerun_backtest`는 기본 체크 상태로 둡니다.
4. 데이터·브라우저 검증을 통과하면 데이터가 저장되고 백테스트가 시작됩니다. 번호 누락, 중복, 날짜 간격 오류, 기존 회차의 다른 값은 저장하지 않습니다.
5. **Validate and deploy Pages**가 검증 후 배포합니다. 먼저 새 데이터가 배포되고, 백테스트 완료 후 결과가 다시 배포됩니다. 계산 중에는 이전 평가의 회차와 재계산 필요 안내가 보일 수 있습니다.

백테스트는 기본 100회 반복, 몬테카를로 10,000회 탐색으로 시간이 걸립니다. 화면의 몬테카를로 탐색은 100,000회여서 평가 조건 차이를 표시합니다. 비용을 낮추려고 횟수를 바꾸면 결과의 변동성도 달라집니다.

실패하면 해당 작업 로그를 확인하고 수정 후 다시 실행합니다. 같은 회차·같은 번호 재입력은 중복 추가하지 않습니다. 데이터가 저장된 뒤 백테스트만 실패했다면 **Re-run Backtest (manual)**을 실행하면 됩니다. 실패한 검증 결과는 배포하지 않아 직전 정상 사이트를 유지합니다. 새 코드의 커밋과 장시간 백테스트의 저장이 충돌하면 푸시는 실패하며, 최신 코드에서 백테스트를 다시 실행해야 합니다.

자동 작업의 푸시만으로는 기존 GitHub Pages 빌드가 실행되지 않을 수 있으므로, Pages 배포 소스를 **GitHub Actions**로 설정합니다. 배포 작업은 `push`, 수동 실행, 데이터/백테스트 작업의 성공 종료를 받습니다. 데이터 쓰기 작업은 같은 동시 실행 그룹으로 겹치지 않게 합니다. GitHub는 같은 그룹의 대기 작업을 무제한 보관하지 않으므로 실행 버튼을 반복해서 누르지 않습니다.

매주 실행되는 예약 수집은 설정하지 않았습니다. 당첨번호 입력은 수동이고 이후 검증·계산·배포가 연결됩니다. 기존 외부 수집 작업도 수동 실행만 가능하며 사이트 차단 등으로 실패할 수 있습니다. 구조 검증은 번호가 공식 발표와 일치하는지까지 증명하지 않으므로 입력 시 원문을 확인합니다.

## 검증 방식

- BSS는 45개 번호의 균등 포함 확률 6/45에 대한 손실 개선율입니다. 음수이면 기준보다 나쁩니다.
- 유의성은 동일 회차의 기준 손실과 모델 손실 차이를 중심화한 단측 부트스트랩 근사 검정입니다. 반복 추출한 100개 추천을 100개의 독립 추첨으로 세지 않습니다.
- 관측 개선이 없으면 보수적으로 `p=1`입니다. 양수 개선에는 `(초과 횟수+1)/(반복 수+1)`을 사용하고 6개 모델에 Bonferroni 보정을 적용합니다. 반복 모델 탐색과 회차 간 의존성까지 해결하는 검정은 아닙니다.
- 기존 301~1241회 결과는 예측·BSS·신뢰구간을 보존하고 잘못된 유의성만 교정했습니다. 메타데이터에 교정 시각과 사유를 남겼으며, 전체 예측을 재실행한 것으로 표시하지 않습니다. 새 실행부터 개별 추천 적중 수의 표준편차를 기록합니다.
- 설정은 301~1100회 성적으로 선택합니다. 1101~1241회는 이미 확인한 회고 평가입니다. 코드와 설정을 고정한 상태에서 1242회부터 새 평가를 누적해야 합니다.
- 베이지안 모델 추정치, 비정규화 결합 점수, 인기 패턴 회피 점수는 실제 당첨확률 또는 검증된 공동당첨 확률이 아닙니다.

## 로컬 검사

Node 22와 Python 3.11 기준입니다.

```sh
npm ci
npx playwright install chromium
npm test
npm run validate
npm run test:browser
```

브라우저 검사는 추천번호·전체 재생성, 통계 초기화 실패의 격리, 임시 복사본의 다음 회차 추가, 결과 파일 로드 실패를 확인합니다. 테스트용 번호는 실제 DB에 쓰지 않습니다.

배포된 사이트 검사:

```sh
SITE_URL=https://shhousekim666-afk.github.io/lotto/ npm run test:browser
```
